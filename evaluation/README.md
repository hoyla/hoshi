# Independent reference evaluation

This evaluation is separate from `calibration/`. It uses human reference
translations from FLORES-200 devtest, not translations generated by Hoshi to
set its checker thresholds. It does not establish that FLORES was absent from
either model's training data, or replace review by a bilingual subject expert.

## Protocol, fixed before inference

- Use the original FLORES-200 archive published by the NLLB team. Verify its
  SHA-256 before reading it. Keep the selected texts, original row numbers,
  article URLs, source archive hash and selection seed together.
- Select eight distinct article URLs from each of `wikinews`, `wikibooks` and
  `wikivoyage`, then one sentence from each selected article. Sort candidate
  URLs before sampling with seed `20261118`. The same 24 aligned examples are
  used for every engine and direction; selection does not use engine outputs.
- Evaluate English, French, Russian, Simplified Chinese, Hebrew and Modern
  Standard Arabic, into and out of English: ten directions per engine.
- Translate one sentence per input file through the production translate
  helper, with the source language explicit. Keep its prompt, splitting,
  generation options and checker thresholds unchanged. These are plain-text
  translation results; they say nothing about document extraction or layout.
- Report corpus chrF++ per direction with SacreBLEU 2.5.1, its full metric
  signature, and the sample size. This measures reference overlap, not the
  probability that a translation is correct. Do not pool different languages
  into an overall quality grade or use this small sample as a release gate.
  Reports also include 1,000-sample paired bootstrap results with a fixed seed.
  These describe sampling uncertainty in reference overlap, not human adequacy;
  uncorrected p-values across ten directions do not declare an overall winner.
- Report engine warnings and checker flags on the human references separately.
  A flag on a reference is a false-alarm candidate requiring review, not proof
  the reference or checker is wrong. A clean engine output is not a quality
  pass. Do not tune thresholds or prompts using these evaluation results.
- Save the source/input/output hashes, complete output text and relevant
  provenance for every case. Record engine digests, runtime versions, helper
  and checker hashes. Reject incomplete or mismatched runs when scoring.
- Export source, human reference and anonymized paired outputs for bilingual
  review. Human findings remain unreviewed until a reviewer supplies them.

The 24 examples are deliberately a small first benchmark. They span three
domains but are sentence-level excerpts, not a representative document corpus.
Small numerical differences cannot establish that one engine is better.

## Reproduce

Preparing the subset requires the archive once; evaluation uses the committed
subset and contacts only the configured local translation services. Model and
service installation remain separate from this evaluation tool.

```bash
python3 evaluation/prepare.py --archive /path/to/flores200_dataset.tar.gz
python3 -m venv .cache/evaluation/venv
.cache/evaluation/venv/bin/python -m pip install -r evaluation/requirements.txt
```

With both engines already running locally:

```bash
python3 evaluation/run.py --engine libre --work .cache/evaluation/libre-run --out evaluation/results/libre.json
python3 evaluation/run.py --engine gemma --work .cache/evaluation/gemma-run --out evaluation/results/gemma.json
.cache/evaluation/venv/bin/python evaluation/score.py --libre evaluation/results/libre.json --gemma evaluation/results/gemma.json --out evaluation/results/report
```

`run.py --help` documents custom service URLs, container name and model. The
runner supports the native Mac and Windows helpers. Scoring needs Perl, which
macOS supplies; Windows can export its runs for scoring on a Mac. Inference
resumes from intact outputs in the same work directory, but a changed engine,
runtime, corpus or production helper requires a new directory. Failed attempts
keep separate logs. Only one runner may use a work directory at a time; a
crash can leave `.evaluation.lock`, which should be inspected before reusing
that directory. Export and report files are never replaced with different data.

The raw helper
outputs and unmodified provenance stay under the ignored work directory;
the portable result records omit machine-specific absolute source paths.

Open `results/report/review.csv` in a UTF-8-aware editor or spreadsheet for
bilingual review; leave `review-key.json` aside until judgments are complete.
For each pair, note which output is better (or a tie), any material omissions,
negation, number or name errors, and the reviewer's notes. The automatic report
does not fill these fields or count them as human findings. Keep a completed
sheet separately rather than replacing the exported blank worksheet.
